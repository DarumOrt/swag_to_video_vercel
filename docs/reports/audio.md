# Аудио-анализ (`src/audio/`): итог

## Публичный API (`@/audio`)

- `analyzeAudio(input: Blob | ArrayBuffer | DecodedAudio, { onProgress?, signal?, sampleRate? = 48000, mono16k? })` → `Promise<{ analysis: AudioAnalysis, pcm: DecodedAudio, mono16k: Float32Array | null }>`: декодирование в main thread, анализ в воркере. Отмена через abort завершает воркер.
- `analyzePcm(pcm, { rate? = 60, onProgress? }): AudioAnalysis`: синхронная чистая функция, работает и в Node (тесты).
- `decodeAudio(blob | arrayBuffer, { sampleRate? })` (только main thread), `toMono16k(pcm)`, `resample(x, from, to)`, `downmixToMono(channels)`.
- `analyzeVocalStem(stem, { rate? })` → `{ vocalOnsets, vocalActivity }`, `applyVocalStem(analysis, stem)` → копия с заменёнными вокальными полями (для стема HTDemucs).
- Константы: `FEATURE_RATE`, `SPECTRUM_*`, `BAND_EDGES_HZ`, `LUFS_FLOOR`, `ML_SAMPLE_RATE`. `DecodedAudio = { sampleRate, channels: Float32Array[], durationSec }`.

## Что готово

- Все поля `AudioAnalysis`, включая v1.1: spectrum (96 лог-полос), rms/peak/LUFS short-term, bands, stereo, `scope` (128 точек на кадр, 32 мс), onsets, vocalOnsets, BPM, биты, даунбиты, `beatStrength`, `vocalActivity`, `sections`.
- 3 минуты анализируются примерно за 2 с в воркере, если машина свободна. Результат детерминирован (проверено тестом и повторным прогоном).
- **Структура (v1.2, `structure.ts`):** `sections[]` получают `role` и `repeatGroup` (группы с 0 по порядку появления, у уникальных тоже своя). По барам: хрома (12) + тембр (24 полосы спектра) + энергия, z-score → самоподобие → новизна (checkerboard 4 такта) добавляет границы там, где звук меняется при той же энергии (куски ≥4 тактов) → average-linkage по сходству секций (порог 0,55, длины в пределах ×2,5) → роли правилами (интро/аутро по краям и энергии, самая громкая повторяющаяся группа = chorus или drop при кинде drop и малом вокале, pre-chorus перед пиком, breakdown, bridge = уникальная во 2-й половине после припева, остальное verse). Цена ~20 мс на 3 мин. Тестов 44 (`structure.test.ts`: A B A B C A, роли на заданных входах).
- 38 тестов на синтетике (до структуры). Dev-страница `dev/audio.html?src=/test-media/<файл>` (порт 5174): спектрограмма с наложениями, лупа, щелчки по битам и онсетам, секции, осциллограф и гониометр.

## Известные проблемы и ловушки

- Кадр i описывает звук около **центра кадра** (i+0.5)/60: окна центрированы, задержки нет. `scope` заканчивается там же, LUFS — скользящие 3 с назад.
- Декодирование всегда в 48 кГц: `decodeAudioData` не сохраняет исходную частоту.
- Шкала спектра **относительная к треку** (99,5-й перцентиль = 1, диапазон 40 дБ, наклон +4,5 дБ/окт). Абсолютных дБ в ней нет.
- bands — это 50% глобальной шкалы и 50% подъёма над скользящей медианой. Поэтому ровный тон даёт 0,5, а не 1 (сделано намеренно, чтобы `low` качал на бочке поверх 808).
- vocalActivity без стема слабая: 89–90% трека на песнях и 77% на инструментале. Нормальная точность только через `applyVocalStem`.
- Трекер битов может встать на хэты на слабых долях, если они громче бочки. Двойной и половинный темп не различается (у IÖN 140 может оказаться «70»).
- Секции: у рэпа с ровной энергией куплет и припев почти не различаются (у Molly первый припев громче всего на ~2,5 дБ).
- В `slidingMedian` (median.ts) буфер окна на 1 элемент больше нужного, потому что вставка идёт раньше удаления. Не «оптимизировать».
- В PowerShell 5.1 `Set-Content -Encoding utf8` пишет BOM. Для файлов кода использовать Write/Edit.

## Что осталось

- Проверить BPM на слух (щелчки на dev-странице), при необходимости добавить выбор между двойным и половинным темпом.
- Подключить `applyVocalStem` после HTDemucs (сессия ML/приложение).
- Предложение по схеме: `onsetStrengths`, чтобы рендер сам выбирал густоту онсетов.
- Подстроить пороги на большем числе треков. Сейчас настроено только на трёх.
- Структура: пороги настроены на синтетике и 3 треках (Toby Mai: verse/chorus/bridge/outro разумно; Molly: A B A B → chorus; IÖN: много chorus/breakdown, на слух не проверено). `vocalActivity` слабая, поэтому «drop vs chorus» держится на `kind==='drop'` + доле вокала (≥0,6 и ≥0,9 от трека = вокальная). Секция из тишины (`sections=[quiet]`) роль не получает: `sectionRole()` выведет по `kind`.
- Границы секций не всегда ровно на смене блока (сетка тактов от даунбитов, ±1 такт).
