# SwagToVideo

Веб-приложение: пользователь загружает трек, добавляет текст песни — и получает видео-визуализацию
(измерители в духе MiniMeters, кинетическая типографика, акценты-эффекты на выбранных словах).
Основной формат — вертикальное видео 9:16 для соцсетей, формат/разрешение/fps настраиваются.

## Ключевые решения (не пересматривать без главной сессии)

- **Всё работает в браузере.** Сервера нет. Хостинг — Vercel Hobby (деплой из GitHub-репозитория).
- **Никаких внешних API-сервисов** (ни LLM, ни сервисов текстов песен, ни облачных GPU).
  npm-библиотеки, собранные в бандл, — можно.
- **Без Remotion.** Рендер-движок свой.
- **ML-модели — только в браузере** (ONNX через transformers.js / onnxruntime-web, WebGPU с WASM-фолбэком).
  Веса лежат в собственном публичном репозитории пользователя на Hugging Face (закреплённые копии),
  кэшируются в браузере (Cache API / OPFS), плюс импорт моделей из файла.
- **Проект некоммерческий**: модели под CC BY-NC допустимы. Код под AGPL в проект не копируем.
- Языки текстов: **RU и EN**.
- Целевой браузер: Chrome/Edge (WebCodecs, WebGPU). Остальные — через feature-detect и фолбэки.
- Заголовки COOP `same-origin` + COEP `credentialless` (SharedArrayBuffer для многопоточного WASM,
  при этом загрузка с Hugging Face работает — проверено). Заданы в `vercel.json` и `vite.config.ts` — держать в синхроне.
- Репозитории моделей на HF: `DarumOrt/whisper-small-timestamped-onnx` (Apache-2.0), `DarumOrt/htdemucs-onnx` (MIT),
  `DarumOrt/aligner-onnx` (CC BY-NC 4.0).
- Репозиторий кода: https://github.com/DarumOrt/swag_to_video_vercel (приватный, `origin`, из него деплоит Vercel).
  Старый `DarumOrt/SwagToVideo` (remote `old`) больше не обновляется. Секреты — только в `.env` (gitignored).

## Команды

```bash
npm run dev        # dev-сервер http://localhost:5173 (с COOP/COEP)
npm run typecheck  # tsc -b
npm run lint       # eslint
npm test           # vitest
npm run build      # прод-сборка в dist/
npm run e2e        # Playwright в установленном Chrome (видимое окно, реальный WebGPU)
```

Перед отчётом прогоняй `typecheck` и тесты/lint своей папки. Импорты внутри `src` — через алиас `@/`.

## Общий контракт

`src/shared/` — типы, которыми обмениваются модули:

- `timeline.ts` — `Timeline` (аудио-признаки, ритм, текст со словами и таймкодами, акценты), `featureIndexAt`;
- `output.ts` — `OutputSettings` (формат, разрешение, fps, контейнер), `DEFAULT_OUTPUT` (1080×1920, 30 fps, MP4);
- `renderer.ts` — `FrameRenderer` (`init` / `renderFrame(N)` / `resize` / `dispose`) и правило детерминизма.

Каждый модуль экспортирует свой публичный API из `src/<модуль>/index.ts`; другие модули импортируют только оттуда.

## Стек

Vite + React + TypeScript, Tailwind + shadcn/ui, Zustand · Web Audio API + Web Workers ·
WebGL2 / Three.js + GLSL, Canvas 2D · WebCodecs + mediabunny · transformers.js (Whisper), onnxruntime-web (HTDemucs).

## Архитектура в одной картинке

```
Трек ─► Аудио-анализ ─┐
Текст ─► ML + Лирика ─┼─► timeline.json ─► Рендер-движок ─► превью (realtime)
Акценты (UI) ─────────┘                         └──────────► Экспорт (offline, покадрово, WebCodecs)
```

`timeline.json` — единый контракт между частями: покадровые аудио-признаки, биты/onsets,
слова с таймкодами и уверенностью, акценты. Рендер детерминирован: превью = экспорт.

## Оркестрация сессий

Главная сессия — координатор: решения, контракты (`src/shared/`), git, сведение работы.
Состояние проекта — `docs/STATUS.md`; память о модулях — `docs/reports/<модуль>.md` (не больше ~40 строк).

### Протокол экономии (действует с вехи 3)

- **Сессия = одна задача.** Свежая сессия с коротким брифом; после отчёта — в архив. Память о модуле живёт
  в `docs/reports/<модуль>.md`, а не в истории сессии. Новая сессия читает `CLAUDE.md`, устав модуля и свой отчёт —
  и больше ничего без нужды.
- **Не больше 2–3 сессий одновременно.**
- **Название сессии** — `SwagToVideo: <модуль> — <задача> · <модель>` (например `… · Sonnet`), чтобы
  пользователь видел модель в списке.
- **Модель по задаче:** Opus — архитектура, рендер, эффекты; Sonnet — фронт, лирика, аудио, экспорт, ML-интеграция;
  Haiku — механика (переименования, документация, простые тесты).
- **Отчёт — файлом.** В конце задачи обнови `docs/reports/<модуль>.md` (API, готово, проблемы и ловушки, что осталось)
  и ответь главной сессии 1–3 строками.
- **Проверки по месту:** свои тесты и lint по своей папке (`npx vitest run src/<модуль>`, `npx eslint src/<модуль>`),
  полный прогон — главная сессия при сведении. В браузере — скриптовые e2e с текстовым выводом; скриншоты
  только когда без них нельзя. Визуальную оценку делает пользователь.
- **Тяжёлые прогоны** (замеры моделей, полный экспорт) — готовой командой, запускает пользователь.
- **Читай точечно:** grep и нужные строки, а не файлы целиком; не исследуй чужие модули без необходимости.

### Правила для тематических сессий

1. Работай только в своих папках. Нужна правка чужой области или общего контракта — опиши её
   и передай главной сессии, сам не меняй.
2. **Не делай git commit/push, не создавай ветки** — это делает только главная сессия.
3. **Не запускай `npm install`** и не правь `package.json` — сессии работают в одной папке, и параллельные
   установки ломают lock-файл. Нужна зависимость — попроси главную сессию (она проверит лицензию и вес).
   Уже установлены: `three`, `mediabunny`, `@huggingface/transformers`, `zustand`, `clsx`, `tailwind-merge`,
   `class-variance-authority`, `lucide-react`, `onnxruntime-web`, `hash-wasm`, `@playwright/test` (dev).
4. Фундаментальные решения из списка выше не пересматривай самостоятельно — предлагай главной сессии.
5. Закончив задачу, обнови `docs/reports/<модуль>.md` и кратко отчитайся главной сессии (см. протокол выше).
6. Ничего не начинай без задачи от пользователя или главной сессии.
7. **Тестовые страницы:** для ручной проверки своего модуля можно делать `dev/<модуль>.html` +
   `src/<модуль>/dev/*`. Vite отдаёт их в dev-режиме (`http://localhost:<порт>/dev/<модуль>.html`),
   в прод-сборку они не попадают. `src/app/` и `index.html` не трогай.
8. **Свой порт dev-сервера** (чтобы сессии не мешали друг другу): `npm run dev -- --port <порт> --strictPort`.
   5173 — главная, 5174 — аудио, 5175 — ML, 5176 — лирика, 5177 — рендер, 5178 — фронт, 5179 — экспорт,
   5180 — эффекты.
9. **Тестовые треки** — в `test-media/` (в `.gitignore`, в репозиторий не попадают). В автотестах
   генерируй синтетический звук (синус, клики, шум), а не реальные треки.
10. **E2E и бенчмарки в браузере** — Playwright (`playwright.config.ts`): установленный Chrome, видимое окно,
    браузеры не скачиваются. Спеки своего модуля — в `e2e/<модуль>/`; свой dev-порт — через
    `E2E_BASE_URL=http://localhost:<порт>` (тогда `webServer` из конфига не запускается).
11. **Бюджет памяти** (у типичного пользователя 8 ГБ и встроенная графика — модели на WebGPU живут в общей RAM):
    тяжёлые этапы (ML, разделение вокала, экспорт) — строго по очереди, по одной модели за раз, воркер
    уничтожается после этапа; по умолчанию лёгкие варианты моделей; большие файлы обрабатываются потоком,
    а не целиком в памяти. Тяжёлые прогоны в браузере (замеры моделей, длинный экспорт) — по одному
    на машину и только после подтверждения пользователя, что машина свободна.
